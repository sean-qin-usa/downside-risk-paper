## job_robust_engine.py (pre-committed; run and harvested in docs/R54_RESULTS_HARVEST.md)

Runs on the compute host against crsp_panel_returns.csv, same 200 names, splits, features and GBM settings as job_frontier_robust.py and job_fz_fullpanel.py, at three- and four-sigma caps.

1. Scale x shape 2x2 on one sort (standard-filter mk63): top decile, deciles 1-9, all asset-days, full decile profile; the robust-filter sort as secondary.
2. Robust-scale engine regulatory battery: FZ0 at 1% and 2.5% (coherent Q*, 20-node ES integral, exact order-statistic conformal shift), breach rates, per-name Kupiec and Christoffersen pass rates, date-clustered exception t, ES over realized on breach days. The standard-scale engine is rebuilt in the same run.
3. Jump-robust GARCH-t as an FZ0 entrant.

Decision rule, fixed in the script header before the run: the text recommends robust scale x flexible shape as the deployed configuration only if, at the three-sigma cap, the robust-scale engine is never worse than the standard-scale engine on FZ0 at both levels (mean difference and DM both >= 0) and is not significantly worse in deciles 1-9 on pinball (DM > -1.96). Otherwise the deployed engine stays on the standard scale and Table 2 reports the decomposition only.

After the run: `python code/paper/make_table_scaleshape.py results/paper/robust_engine_results.json` prints the one-sort table and the numbers; add `--write` to replace the Table 2 body between its markers. The overall cells should reproduce frontier_robust (0.353, 0.423, 0.524); the script prints the comparison. Prose for the recommendation (intro, Section 4 scale-versus-shape paragraph, Section 5, conclusion) is written after the result, per the decision rule.
